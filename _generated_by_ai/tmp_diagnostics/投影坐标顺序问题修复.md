# 投影坐标顺序问题 - 根本原因和修复

## 🔍 问题根源

测试结果显示投影质量很差：
- 覆盖率只有 5.6% (应该 > 30%)
- 边界内比例只有 75.1% (应该 > 95%)
- **Y 坐标超出图像高度**: y_max=309 但图像高度=240

## 🐛 Bug 定位

### `utils/fusion_util.py` 第 81-82 行

```python
def compute_mapping(self, camera_to_world, coords, depth=None, intrinsic=None):
    # ... 投影计算 ...
    
    # 🔥 关键: mapping 的顺序是 [y, x, valid]
    mapping[0][inside_mask] = pi[1][inside_mask]  # 第0行存 y (行索引)
    mapping[1][inside_mask] = pi[0][inside_mask]  # 第1行存 x (列索引)
    mapping[2][inside_mask] = 1                   # 第2行存 valid
    
    return mapping.T  # 返回 (N, 3): [y, x, valid]
```

**返回格式**: `mapping[:, 0]` 是 **y 坐标**，`mapping[:, 1]` 是 **x 坐标**

### `dataset/data_loader.py` 第 326-329 行

```python
# 🔥 Bug: 把 y 当成 x，把 x 当成 y
x_label = single_mapping[:, 0][single_mapping[:, 0] != 0]  # 实际上是 y!
y_label = single_mapping[:, 1][single_mapping[:, 1] != 0]  # 实际上是 x!
x_label = torch.from_numpy(x_label).long()
y_label = torch.from_numpy(y_label).long()
```

**结果**: x 和 y 坐标完全颠倒！

### 为什么测试结果很差？

1. **Y 坐标超出边界**: 
   - 真实 x 范围 [10, 229] (宽度 320 内)
   - 被当成 y，但图像高度只有 240
   - 所以 y_max=229 没问题，但 x_max=309 超出高度 240

2. **覆盖率低**: 
   - 很多点因为坐标颠倒而被判定为越界
   - 实际可见的点被错误过滤掉

3. **边界检查失败**:
   - `criterion.py` 中检查 `x_idx < W` 和 `y_idx < H`
   - 但坐标颠倒后，检查逻辑也错了

## ✅ 修复方案

### 方案 1: 修改 `data_loader.py` (推荐)

修改 `dataset/data_loader.py` 第 326-329 行：

```python
# 修复前 (错误)
x_label = single_mapping[:, 0][single_mapping[:, 0] != 0]  # 错: 这是 y
y_label = single_mapping[:, 1][single_mapping[:, 1] != 0]  # 错: 这是 x

# 修复后 (正确)
y_label = single_mapping[:, 0][single_mapping[:, 0] != 0]  # 正确: 第0列是 y
x_label = single_mapping[:, 1][single_mapping[:, 1] != 0]  # 正确: 第1列是 x
x_label = torch.from_numpy(x_label).long()
y_label = torch.from_numpy(y_label).long()
```

### 方案 2: 修改 `fusion_util.py` (不推荐)

修改 `utils/fusion_util.py` 第 81-82 行：

```python
# 修复前 (OpenScene 原始顺序)
mapping[0][inside_mask] = pi[1][inside_mask]  # y
mapping[1][inside_mask] = pi[0][inside_mask]  # x

# 修复后 (改为 x, y 顺序)
mapping[0][inside_mask] = pi[0][inside_mask]  # x
mapping[1][inside_mask] = pi[1][inside_mask]  # y
```

**不推荐原因**: 
- 会影响其他使用 `fusion_util.py` 的代码
- OpenScene 原始实现就是这个顺序
- 应该在使用处适配，而不是修改底层工具

## 📚 参考

### OpenScene 原始实现

OpenScene 的 `fusion_util.py` 返回 `[y, x, valid]` 顺序是有意设计的：
- `y` 对应图像的**行索引** (height 维度)
- `x` 对应图像的**列索引** (width 维度)
- 这符合 numpy 数组的 `[row, col]` 索引习惯

### 正确的使用方式

```python
# OpenScene 原始代码 (正确)
mapping = mapper.compute_mapping(pose, coords, depth)
# mapping[:, 0] 是 y (行)
# mapping[:, 1] 是 x (列)

# 访问 2D 图像/mask
mask_2d = masks[mapping[:, 0], mapping[:, 1]]  # [y, x] 顺序
# 或
mask_2d = masks[:, mapping[:, 0], mapping[:, 1]]  # (K, H, W) 格式

# 存储为 x_label, y_label 时要注意
y_label = mapping[:, 0]  # 第0列是 y
x_label = mapping[:, 1]  # 第1列是 x
```

## 总结

**问题**: `data_loader.py` 中把 `compute_mapping` 返回的 `[y, x, valid]` 当成了 `[x, y, valid]`

**影响**: 
- 坐标完全颠倒
- 投影质量很差
- 训练无法正常进行

**修复**: 交换 `x_label` 和 `y_label` 的赋值

**重要**: 在 `open_vocab_dataset_v2.py` 中添加运行时投影时，必须使用正确的坐标顺序！
