# 投影标签 (x_label/y_label) 问题解决方案

## 问题描述

运行训练命令时:
```bash
python train_open_vocab_v2.py --config config/train_scannet_v2_minimal.yaml --num-epochs 5
```

会发现 `x_label` 没有,导致训练无法正常进行。

## 问题根源

### 1. 数据格式问题

当前的 `.pth` 文件是**旧格式**:
```python
# 旧格式: tuple (locs, feats, labels)
data = (
    locs,    # (N, 3) - 3D 坐标
    feats,   # (N, 3) - RGB 特征
    labels   # (N,)   - 语义标签
)
```

**缺少** `x_label` 和 `y_label`,这两个是 3D 点投影到 2D 图像的坐标。

### 2. x_label 和 y_label 的作用

在 3D-2D 融合训练中:
- `x_label[i]`: 第 i 个 3D 点投影到 2D 图像的 **x 坐标**(列)
- `y_label[i]`: 第 i 个 3D 点投影到 2D 图像的 **y 坐标**(行)

这些标签用于建立 3D 点和 2D mask 的对应关系:
```python
# criterion.py 中的使用
gt_3d = mask_2d[:, y_idx, x_idx]  # 从 2D mask 中提取对应 3D 点的 GT
```

### 3. 当前代码的处理

`dataset/open_vocab_dataset_v2.py` 中的 `_load_3d_simple()` 函数:
```python
# 尝试从 .pth 中读取
x_label = data.get("x_label") if isinstance(data, dict) else None
y_label = data.get("y_label") if isinstance(data, dict) else None

if x_label is None or y_label is None:
    # ⚠️ 使用全零占位符
    print(f"Warning: x_label/y_label not found, using zeros")
    x_label = torch.zeros(N, dtype=torch.long)
    y_label = torch.zeros(N, dtype=torch.long)
```

**问题**: 全零的 `x_label/y_label` 会导致:
1. `criterion.py` 中所有 batch 被跳过
2. Loss 返回 0,无法反向传播
3. 训练实际上没有进行

### 方案 2: 运行时动态计算投影 (临时方案)

如果不想重新生成数据(例如磁盘空间不足),可以在运行时动态计算投影。

**缺点**: 
- 训练速度会**显著降低**(每个 epoch 都要重新计算投影)
- 增加内存占用(需要读取 2D 图像和深度图)

## 技术细节

### 投影计算原理

3D 点到 2D 图像的投影使用相机投影矩阵:

```python
# 世界坐标 -> 相机坐标
p_camera = world_to_camera @ p_world

# 相机坐标 -> 图像坐标
x = (p_camera[0] * fx) / p_camera[2] + cx
y = (p_camera[1] * fy) / p_camera[2] + cy
```

其中:
- `world_to_camera`: 相机外参(位姿的逆)
- `fx, fy, cx, cy`: 相机内参

### 为什么需要深度图?

深度图用于**可见性检查**:
- 只有在相机视野内且未被遮挡的点才是有效投影
- 通过比较投影深度和实际深度图判断可见性

### 数据格式对比

**旧格式** (tuple):
```python
(locs, feats, labels)
```

**新格式** (dict):
```python
{
    "locs": locs,           # (N, 3)
    "feats": feats,         # (N, 3)
    "labels": labels,       # (N,)
    "x_label": x_label,     # (N,) - 投影 x 坐标
    "y_label": y_label,     # (N,) - 投影 y 坐标
}
```

## 常见问题

### Q1: 为什么之前的对话判断不应该缺少 x_label?

**A**: 可能是基于以下假设:
1. 假设数据已经预处理好,包含投影标签
2. 假设代码会自动计算投影

但实际上:
- ScanNet 原始数据**不包含**投影标签
- 需要使用相机参数**手动计算**
- 当前代码只是用零填充,并不真正计算

### Q2: 生成投影标签需要多长时间?

**A**: 取决于数据量:
- 单个场景: ~10-30 秒
- 977 个训练场景: 约 3-8 小时

建议:
- 先处理少量场景测试(使用 `--scene-pattern "scene0000*"`)
- 确认无误后再处理全部数据
- 可以并行处理(修改脚本使用多进程)

### Q3: 如果没有 2D 数据怎么办?

**A**: 无法训练 3D-2D 融合模型,因为:
- 需要 2D mask 作为监督信号
- 需要投影坐标建立 3D-2D 对应关系

解决方案:
1. 下载完整的 ScanNet 数据集(包括 RGB、深度、位姿)
2. 或使用纯 3D 的训练方法(不需要 2D 数据)

### Q4: 为什么不在训练时实时计算投影?

**A**: 性能考虑:
- 投影计算需要读取图像、深度图
- 每个 epoch 都重复计算浪费时间
- 预计算一次,后续训练快很多

但如果:
- 磁盘空间不足
- 只是快速测试
- 数据量很小

可以使用方案 2 的动态计算。

## 验证训练是否正常

训练开始后,检查以下指标:

### 1. Loss 不应该为 0

```
Epoch [1/5] Step [0/100] Loss: 0.8234 (0.8234) LR: 5.00e-05 ETA: 120s
```

如果看到 `Loss: 0.0000`,说明投影标签仍然有问题。

### 2. 不应该有大量警告

正常情况下,偶尔会有:
```
Warning: 12/50000 points out of bounds after scaling, skipping
```

但不应该每个 batch 都有:
```
Warning: All x_label/y_label are 0 for batch 0, skipping
```

### 3. 检查 TensorBoard

```bash
tensorboard --logdir runs/open_vocab_3d_v2_minimal2
```

Loss 曲线应该:
- 初始值合理(0.5-2.0)
- 逐渐下降
- 不是一直为 0
